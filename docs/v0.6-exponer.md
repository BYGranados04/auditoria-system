# Auditoria System v0.6 - EXPONER

## Objetivo

v0.6 incorpora una API HTTP local de solo lectura para consultar la información recopilada por Auditoria System sin modificar el estado del servidor ni ejecutar respuestas defensivas.

## Endpoints

- `GET /health`: disponibilidad del proceso HTTP.
- `GET /status`: hostname, modo de respuesta, bloqueo automático, total de eventos, bloqueos activos y conteo por severidad.
- `GET /events`: eventos con filtros por severidad, tipo, hostname, categoría, rango temporal y límite.
- `GET /detections`: únicamente eventos de categoría `detection`.
- `GET /responses`: únicamente `RESPONSE_DECISION` y `RESPONSE_EXECUTION`.

Los filtros temporales requieren zona horaria y `limit` admite de 1 a 1000.

## Seguridad

La API se ejecuta como `auditoria-api`, sin privilegios administrativos. Accede a SQLite mediante `EventRepository(read_only=True)`, `mode=ro` y `PRAGMA query_only = ON`.

ACL aplicada:

- `/var/lib/auditoria-system`: `--x`
- `/var/lib/auditoria-system/auditoria.db`: `r--`

No existe ACL por defecto para archivos futuros. La API no puede leer `agent_state.json` ni el directorio de logs.

`auditoria-api.service` utiliza endurecimiento systemd, incluyendo `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, restricciones de namespaces y capacidades vacías.

Uvicorn escucha exclusivamente en `127.0.0.1:8000`. v0.6 no agrega reglas UFW ni expone la API por LAN, Tailscale o interfaces públicas.

No existen endpoints HTTP para crear, modificar o borrar eventos, cambiar configuración, ejecutar bloqueos ni modificar el firewall.

## Instalación

`scripts/instalar-servicio.sh` instala agente y API de forma idempotente. Crea el usuario `auditoria-api` si falta, inicia el agente, espera `auditoria.db`, aplica ACL mínimas, comprueba lectura sin escritura y habilita ambos servicios.

## Validación

En `auditoria-server` se comprobó:

- agente activo;
- API activa y habilitada;
- listener `127.0.0.1:8000`;
- conexión LAN al puerto 8000 rechazada;
- `POST /events` responde HTTP 405;
- los cinco endpoints consultan la base real;
- suite automatizada: `176 passed`.

## Limitaciones

v0.6 es local y no incluye autenticación HTTP, autorización por roles, TLS, acceso remoto, dashboard web, notificaciones ni ejecución de respuestas por HTTP.

`evidence` puede contener IP, nombres de usuario y otros metadatos operativos. Antes de exponer la API remotamente se deberán añadir autenticación, autorización y revisión de campos publicados.

FastAPI mantiene OpenAPI y documentación interactiva disponibles en la interfaz local.
