# Autenticación de Auditoria System v0.7

La autenticación utiliza una base independiente en
`/var/lib/auditoria-system-auth/auth.db`. La API mantiene
`/var/lib/auditoria-system/auditoria.db` en modo de solo lectura.

## Contraseñas

Las contraseñas se derivan con `hashlib.scrypt` y un salt aleatorio de
16 bytes por usuario. Los parámetros de producción son:

- `N=2^15`
- `r=8`
- `p=3`
- `dklen=64`
- `maxmem=256 MiB`

Los parámetros se guardan junto al hash para permitir una migración futura.
La contraseña se limita a 1024 bytes y nunca se registra ni se almacena en
texto plano o mediante cifrado reversible.

## Sesiones y CSRF

Cada login genera dos valores aleatorios independientes de 32 bytes:

- token de sesión, enviado en una cookie `HttpOnly`;
- token CSRF, enviado en una cookie separada y en el encabezado
  `X-CSRF-Token` para operaciones mutables autenticadas.

`auth.db` almacena únicamente digest SHA-256 de ambos valores. Las cookies
usan `SameSite=Strict`, `Path=/` y una expiración de ocho horas. La variable
`AUDITORIA_AUTH_COOKIE_SECURE=true` habilita `Secure` cuando exista HTTPS.
Las mutaciones también rechazan encabezados `Origin` o `Referer` que no
coincidan con el origen de la API.

## Superadmin inicial

No existen credenciales predeterminadas. Después de instalar, ejecutar como
el usuario del servicio:

```bash
runuser -u auditoria-api -- /opt/auditoria-system/.venv/bin/python \
  -m app.auth create-superadmin
```

El comando solicita usuario y contraseña dos veces mediante `getpass`; la
contraseña no se acepta como argumento.

## Permisos de despliegue

La unidad conserva `ProtectSystem=strict` y declara:

```ini
StateDirectory=auditoria-system-auth
StateDirectoryMode=0700
```

Solo `auditoria-api` puede escribir en ese directorio. No se concede escritura
sobre `/var/lib/auditoria-system` ni sobre `auditoria.db`.
